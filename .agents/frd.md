## 1. 문서 목적

이 문서는 ZANI MVP에서 사용자가 무엇을 할 수 있어야 하고, 시스템이 각 상황에서 어떻게 동작해야 하는지를 정의한다. 기획, 디자인, 개발, QA가 같은 기준으로 범위와 완료 조건을 이해하는 것이 목적이다.

## 2. 제품 한눈에 보기

ZANI는 실시간 온라인 강의와 수업 후 복습을 연결하는 강의 플랫폼이다.

수업 중에는 학생 브라우저가 시선·머리·상체의 관측 가능한 특징을 10초 단위로 분석해 참여 상태를 판정한다. 학생 카메라 영상은 라이브 WebRTC 수업을 위해 SFU를 통해 다른 참여자에게 전달되지만, 분석 목적으로 별도 전송하거나 녹화하지 않는다. 확인이 필요해 보이는 상태가 이어지면 학생에게 짧은 자기보고 프롬프트를 보여준다. 여러 학생에게 같은 흐름이 나타나면 강사에게 개인 이름이 아닌 집단 팁을 제공하고, 이때 강사의 최근 발화를 전사해 팁 문구에 수업 맥락을 채운다.

수업이 끝나면 강사 카메라, 공유 화면, 전체 음성을 녹화한 자료와 전사, 수업 이벤트, 채팅, 강사 사후 메모를 SSAFY GMS가 분석한다. 강사는 익명 집단 집중 흐름 타임라인과 수업 개선 피드백이 포함된 전체 수업 리포트를 확인한다. 학생은 공통 녹화·전사, 본인의 집중 흐름 타임라인과 근거가 있는 복습 추천을 확인한다.

ZANI는 참여 상태를 약한 신호로만 사용한다. 학생에게 제공하는 `집중 흐름(참고용)`은 구간별 참여도 단계 평균을 시간축에 표현한 파생 지표이며, 실제 이해도나 인지 상태를 확정하는 점수가 아니다. 개인별 결과는 성적·출석·징계·순위에 사용하지 않으며 강사에게 공개하지 않는다.

## 3. 목표와 성공 기준

### 3.1 제품 목표

1. 강사가 비대면 수업에서 집단적인 확인 필요 시점을 놓치지 않게 한다.
2. 학생이 수업 흐름을 방해받지 않고 현재 상태를 짧게 표현하게 한다.
3. 수업 녹화, 전사, 이벤트, 강사 메모를 연결해 근거가 있는 복습 후보를 제공한다.
4. 학생 원본 카메라 영상을 서버에 저장하지 않는다.
5. 자동 분석 결과를 개인 평가가 아닌 확인과 복습 지원에만 사용한다.
6. 학생이 본인의 집중 흐름과 복습 근거를 수업 타임라인에서 확인하고 해당 녹화 구간으로 이동하게 한다.
7. 강사가 익명 집단 흐름, 학생 자기보고, 질문, 전사와 수업 이벤트를 함께 보고 수업 개선 후보를 판단하게 한다.

### 3.2 MVP 측정 지표

| 구분 | 지표 | 목표 |
| --- | --- | --- |
| 사용 | 학생 체크 프롬프트 응답률 | 60% 이상 |
| 사용 | 학생 복습 추천 다시 보기 실행률 | 40% 이상 |
| 사용 | 수업 후 리포트 열람률 | 70% 이상 |
| 품질 | 동일 강사 기준 수업당 집단 팁 | 평균 3회 이하 권장 |
| 성능 | 공식 지원 동시 접속 | 30명까지 안정 동작 |
| 성능 | 학생 이벤트 서버 도착 지연 | 3초 이하 |
| 처리 | 실시간 팁 생성 | 트리거 후 15초 이내 |
| 처리 | 전체 사후 결과 생성 | 강사 메모 확정 후 8시간 이내 |

추천 관련성 평가 UI와 분석 동의율 지표는 MVP 범위에서 제외한다.

## 5. 사용자와 역할

### 5.1 전역 계정

모든 사용자는 같은 형태의 계정을 사용한다. 계정에 강사 또는 학생 역할을 영구 저장하지 않는다.

### 5.2 수업방 역할

- 방을 만든 사용자는 해당 방의 `강사`가 된다.
- 초대 링크나 참여 코드로 들어온 사용자는 해당 방의 `학생`이 된다.
- 한 사용자는 어떤 방에서는 강사이고 다른 방에서는 학생일 수 있다.

| ID | 요구사항 |
| --- | --- |
| ROLE-001 | 시스템은 사용자 역할을 수업방 참여 관계에 저장해야 한다. |
| ROLE-002 | 방 생성자만 해당 방의 강사 권한을 가져야 한다. |
| ROLE-003 | MVP는 공동강사·조교 승격 기능을 제공하지 않아야 한다. |
| ROLE-004 | 역할은 LiveKit 토큰 `metadata`로 전달하고 클라이언트가 임의로 정하지 않아야 한다. |

## 6. 전체 사용자 여정

### 6.1 강사 여정

1. Google 계정으로 로그인하고 최초 약관에 동의한다.
2. 수업 제목을 입력하고 방을 만든다.
3. 수업방에 연결하면 수업이 시작되고 수업 시간과 녹화가 시작된다.
4. 초대 링크나 참여 코드를 학생에게 전달한다.
5. 실시간 강의를 진행하고 집단 팁을 확인한다.
6. 필요하면 학생을 음소거하거나 화면 공유를 중지한다.
7. `수업 종료` 버튼을 누르거나, 3시간이 지나 자동 종료된다.
8. 녹화 구간을 선택해 사후 메모를 한 번 작성하거나 메모 없이 완료한다.
9. 이메일을 받은 뒤 익명 집단 타임라인과 수업 개선 피드백이 포함된 전체 리포트를 확인한다.

### 6.2 학생 여정

1. Google 계정으로 로그인하고 최초 약관에 동의한다.
2. 초대 링크나 참여 코드를 입력한다.
3. 카메라·마이크 테스트를 모두 통과한다.
4. 진행 중인 수업에 즉시 입장한다.
5. 수업 중 채팅, 손들기, 이모지 반응을 사용하고 확인 프롬프트에 응답한다.
6. 이메일을 받은 뒤 공통 녹화·전사, 본인 집중 흐름 타임라인과 복습 추천을 확인한다.

## 7. 계정·약관·로그인

### 7.1 Google 로그인

- 로그인 수단은 Google OAuth만 제공한다.
- 최초 로그인 시 Google 계정의 고유 식별자, 표시 이름, 이메일, 프로필 이미지를 계정에 연결한다.
- 이메일·비밀번호 회원가입과 비밀번호 재설정은 제공하지 않는다.
- Access Token은 `Authorization: Bearer` 헤더로 전달하고 유효기간은 1시간이다. Refresh Token은 HttpOnly 쿠키로만 오가며 재발급마다 회전한다.

### 7.2 최초 필수 약관

최초 로그인 사용자는 다음 내용을 포함한 필수 약관에 동의해야 계정을 생성할 수 있다.

- 강사 카메라, 현재 공유 화면, 전체 참여자 음성 녹화
- 수업 전사, 요약, 복습 추천을 위한 데이터 처리
- 학생 브라우저의 시선·머리·상체 특징 분석
- 참여 상태 이벤트, 개인 집중 흐름 파생값, 확인 응답, 채팅, 접속 기록 저장
- SSAFY GMS 분석을 위한 가명화 데이터 처리
- 90일 기본 보관과 강사 수동 삭제

수업 입장 시에는 별도 동의 버튼을 다시 받지 않지만, 현재 수업이 녹화·분석된다는 사실을 명확히 고지한다.

> 필수 분석 동의 정책과 약관 문구는 파일럿 전 개인정보·법률 검토를 거쳐야 한다.

| ID | 요구사항 |
| --- | --- |
| AUTH-001 | 사용자는 Google OAuth로 로그인·로그아웃할 수 있어야 한다. |
| AUTH-002 | 최초 약관에 동의하지 않은 사용자는 계정을 생성하거나 서비스에 진입할 수 없어야 한다. |
| AUTH-003 | 약관 버전, 동의 시각, 사용자 ID를 저장해야 한다. |
| AUTH-004 | 인증이 만료된 이메일 링크는 로그인 후 원래 권한 확인 화면으로 돌아와야 한다. |
| AUTH-005 | 모든 보호 API는 Bearer 헤더로만 인증하고 쿠키는 Refresh 전용으로 사용해야 한다. |

## 8. 수업방 생성·입장·상태

### 8.1 방 생성

- 강사는 제목을 입력하고 방을 생성한다. 예약 일시나 반복 일정은 받지 않는다.
- 방을 만든 직후는 **준비 상태**다. 아직 수업이 시작되지 않았고 초대 코드로 학생이 입장할 수 없다.
- **강사가 실제로 수업방에 연결한 뒤에 수업이 시작된다.** 이때 상태가 `LIVE`가 되고 수업 시간과 녹화가 시작되며 초대 코드가 활성화된다. 강사가 연결하지 못하면 수업은 시작되지 않고, 준비 상태로 남은 방은 학생에게 노출되지 않는다.
- 한 계정은 동시에 하나의 준비·진행 방만 가질 수 있다.
- 강사 카메라를 사용할 수 없으면 제한 모드로 시작할 수 있다. 제한 모드에서는 화면 공유와 음성을 녹화하고 강사 비언어 분석만 제외한다.

### 8.2 초대와 입장

- 시스템은 초대 링크와 8자리 참여 코드를 함께 발급한다.
- 학생은 유효한 링크·코드로 접속하면 강사 승인 없이 입장한다. 같은 코드로 다시 입장해도 참가자를 새로 만들지 않는다(멱등).
- 방 생성 이후 언제든 늦게 입장할 수 있다.
- **실제로 수업방에 연결해 미디어가 붙은 순간** 사후 자료 접근 자격을 얻는다. 초대 코드로 입장 API만 호출하고 연결에 성공하지 않으면 자격을 얻지 않는다. 다른 학생 음성이 담긴 녹화·전사에 수업을 듣지 않은 사람이 접근하지 않게 하는 조건이다.

### 8.3 수업 시간과 인원

- 최대 진행 시간은 3시간이다. 종료 예정 시각은 `시작 시각 + 3시간`이며 강의실 진입 응답으로 전달한다. 여기서 `시작 시각`은 방을 만든 시각이 아니라 강사 연결로 `LIVE`가 된 시각이다.
- 자동 종료 10분 전부터 강사·학생 화면에 남은 시간을 안내한다.
- 3시간이 되면 서버 스케줄러가 수업을 자동 종료한다.
- 강사는 언제든 `수업 종료`를 눌러 직접 종료할 수 있다.
- 제품은 입장 인원 하드 캡을 두지 않는다. 동시 30명까지 공식 성능 보장 대상으로 삼는다.

### 8.4 종료 경로

종료는 세 경로에서 발생하며 모두 같은 처리를 거친다. 이미 종료된 수업에 대한 종료 요청은 오류가 아니라 현재 상태를 돌려준다(멱등).

| 경로 | 사유 | 판단 주체 |
| --- | --- | --- |

## 9. 입장 전 기기 테스트

학생은 수업방에 들어가기 전에 다음을 모두 통과해야 한다.

1. 공식 지원 환경 확인: Windows 또는 macOS의 최신 데스크톱 Chrome
2. 카메라 권한과 실제 영상 입력 확인
3. 마이크 권한과 입력 레벨 확인
4. 선택한 카메라·마이크 미리 보기
5. 현재 수업의 녹화·분석 고지 확인

카메라 또는 마이크 테스트가 실패하면 입장할 수 없다. 시스템은 권한 거부, 장치 없음, 다른 앱에서 사용 중, 지원하지 않는 브라우저를 구분해 해결 방법을 안내한다. 점검에서 고른 장치는 강의실에서 그대로 이어 쓴다.

| DEVICE-002 | 지원하지 않는 브라우저·기기에서는 입장 대신 지원 환경 안내를 표시해야 한다. |

## 10. 실시간 강의실

### 10.1 오디오·비디오

- 모든 참여자는 자신의 마이크와 카메라를 켜고 끌 수 있다. 토글은 실제 트랙 publish 상태를 바꾼다.
- 학생 카메라 영상은 라이브 전송에는 사용하지만 녹화물에는 포함하지 않는다.
- 강사 카메라 영상은 녹화와 강사 비언어 강조 구간 분석에 사용한다.
- 강사 카메라가 수업 도중 사용할 수 없게 되면 제한 모드로 전환하고 강사에게 상태를 알린다.
- 서버가 특정 source의 publish 권한을 회수하면(강사 제한 모드) 해당 장치 조작을 막고 제한 상태를 화면에 표시한다.

### 10.2 화면 공유

- 강사와 학생 모두 화면을 공유할 수 있다. **강사 승인은 필요하지 않다.**
- **한 세션에 활성 공유는 하나다.** 이미 공유 중인 사람이 있으면 다른 사람은 공유를 시작할 수 없다. 먼저 시작한 쪽이 유지되며, 나중에 시작하려는 쪽이 기존 공유를 밀어내지 못한다.
- 강사는 학생의 화면 공유를 언제든 중지할 수 있다. 강사가 공유하려면 진행 중인 학생 공유를 먼저 중지시킨다.
- 단일성 판정은 서버가 소유한다. 화면에서 버튼을 숨기는 것으로 대신하지 않는다.
- 현재 활성화된 공유 화면은 강사 카메라·전체 음성과 함께 녹화한다.

### 10.3 채팅

- 공개 채팅은 현재 참여자 모두에게 보인다.
- 학생은 강사에게만 보이는 1:1 메시지를 보낼 수 있다. 학생 간 1:1 메시지는 제공하지 않는다.
- 공개 채팅은 공통 질문·채팅 요약에 사용한다.
- 학생-강사 1:1 메시지는 해당 학생의 개인 추천과 강사 리포트에만 사용한다.

### 10.4 손들기·이모지·참가자 목록

- 학생은 손들기 상태를 켜고 끌 수 있고, 강사는 순서를 확인하고 내릴 수 있다.
- 이모지 반응은 모든 참여자에게 일시적으로 표시한다.
- 참가자 목록에는 표시 이름, 마이크·카메라·손들기·화면공유 상태를 표시한다.
- 채팅·이모지·손들기가 없다는 사실 자체는 확인 필요 신호로 사용하지 않는다.

### 10.5 강사 제어

- 강사는 학생 마이크를 음소거할 수 있고, 강제로 켤 수는 없다.
- 강사는 학생 화면 공유를 중지할 수 있다.
- **강제 퇴장 기능은 제공하지 않는다.**

### 10.6 연결 상태와 presence

- 모든 참여자는 접속 중 서버에 10초 주기로 presence heartbeat를 보낸다. 서버는 Redis TTL 30초로 접속 여부를 관리한다.
- heartbeat에는 연결 상태(`CONNECTED`·`RECONNECTING`·`DISCONNECTED`)를 함께 보낸다.
- 학생 연결이 끊기면 자동 재연결을 시도하고, 실패하면 재입장 화면을 제공한다.
- 재연결·재입장 구간은 분석 자체가 불가능하므로 참여 상태를 만들지 않는다(§11.6의 이름 구분 참조).
- 강사 연결이 비정상적으로 끊기면 5분 유예를 시작한다. 유예가 지난 뒤에도 강사가 돌아오지 않으면 수업을 종료한다. 학생 화면에는 유예 중임과 종료 사실을 안내한다.
- **이탈 감지와 종료는 클라이언트의 이탈 보고에 의존하지 않아야 한다.** 브라우저 창이 그대로 닫히거나 강제 종료되거나 네트워크가 끊기면 `DISCONNECTED` heartbeat가 서버에 도달하지 않는다. 참여자가 전원 이탈해 heartbeat가 아무도 오지 않는 상황에서도 유예 시작과 자동 종료가 일어나야 한다.
- 최대 진행 시간(3시간) 도달에 의한 종료만으로는 이 요구를 충족하지 못한다. 1시간 만에 실질적으로 끝난 수업이 남은 2시간 동안 `LIVE`로 남아 있으면 안 된다. 그 사이 녹화가 계속되고, 이미 발급된 미디어 토큰으로 재입장할 수 있기 때문이다.

| ID | 요구사항 |
| --- | --- |
| LIVE-001 | 시스템은 동시 오디오·비디오 송수신을 지원해야 한다. |
| LIVE-002 | 화면 공유는 역할 제한 없이 시작할 수 있어야 하고, 한 세션에 활성 공유가 하나임을 서버가 보장해야 한다. |
| LIVE-003 | 공개 채팅과 학생-강사 1:1 채팅의 열람 범위를 분리해야 한다. |
| LIVE-004 | 시스템은 손들기, 이모지, 참가자 상태를 실시간 동기화해야 한다. |
| LIVE-005 | 강사는 학생 음소거와 공유 중지를 수행할 수 있어야 한다. |
| LIVE-006 | 강사 비정상 이탈 후 5분 유예와 자동 종료가 동작해야 한다. |
| LIVE-007 | 미디어 토글은 로컬 화면 상태가 아니라 실제 publish 상태를 반영해야 한다. |
| LIVE-008 | presence heartbeat 주기는 서버 TTL보다 충분히 짧아야 한다. |
| LIVE-009 | 강사 이탈 감지와 자동 종료는 클라이언트의 이탈 보고 없이도 동작해야 한다. |
| LIVE-010 | 참여자가 전원 이탈해도 수업은 최대 진행 시간을 기다리지 않고 종료되어야 한다. |

## 11. 학생 카메라 분석과 참여 상태

### 11.1 처리 원칙

- MediaPipe Face Landmarker 기반 특징 추출과 참여도 모델 추론은 학생 브라우저에서 실행한다.
- 프레임 표본 추출 주기는 초당 10프레임이다. 10초 창 하나에 100장이 들어간다.
- 창을 판정에 쓸 수 있는지는 유효 프레임 비율로 정한다. 기준은 [`attention-coaching-context.md`](./attention-coaching-context.md) §3.2 를 따른다.
- 학생 원본 프레임과 랜드마크 원본을 분석 API로 보내거나 영구 저장하지 않는다.
- 서버에는 **10초 단위 판정 결과와 프롬프트 응답만** 전송한다.
- 분석은 이해도를 확정하는 수단이 아니라 확인 질문, 개인 집중 흐름, 복습 후보와 익명 집단 피드백을 만들기 위한 약한 신호다.

### 11.2 공통 특징 스키마

배포 계약은 `mediapipe_98_v1`이다. 프레임 하나에서 49차원을 뽑고, 10초 창을 20구간(각 500ms)으로 나눠 구간마다 평균 49개와 표준편차 49개를 이어 98차원을 만든다. 모델 입력은 `20 × 98` 텐서다.

브라우저와 오프라인 학습 전처리는 같은 MediaPipe 모델 파일, 특징 계산식, 정규화 방식, 스키마 버전을 사용해야 한다. 스키마 이름과 입력 shape 은 배포된 모델 메타데이터(`engagement.metadata.json`)가 소유하며, 불일치하면 브라우저가 모델을 거부한다.

상체 자세(Pose Landmarker) 특징은 이 계약에 포함되지 않는다. 초기 시각 모델은 얼굴 특징만 사용한다.

### 11.3 개인 기준선 (보류)

확정된 판정 흐름에는 개인 기준선 단계가 없다. 모델이 절대값을 그대로 받는다.

이 절은 티켓 74(`calibration.ts` 8초 개인 기준선)와 함께 판단해야 하므로 삭제하지 않고 보류로 남긴다. 기준선을 도입하려면 특징 계산식이 바뀌므로 `mediapipe_98_v1` 재학습이 필요하다.

### 11.4 참여도 모델과 10초 판정

- 모델은 4단계 각각의 확률을 출력한다: `Not-Engaged`(1) · `Barely-Engaged`(2) · `Engaged`(3) · `Highly-Engaged`(4)
- 판정 단위는 **10초**다(모델 입력 텐서 `20 × 98`과 묶인 구조값이라 이 문서가 소유한다). 10초마다 판정 1건을 만든다.
- 저참여로 볼지는 가장 높은 단계가 아니라 **1·2단계 확률의 합**으로 정한다. 기준값은 [`attention-coaching-context.md`](./attention-coaching-context.md) §3.3 을 따른다.
- **3·4단계** → 그 학생은 `GOOD`이며 프롬프트를 띄우지 않는다.
- **저참여**나 **얼굴 판단 불가**가 정해진 횟수만큼 연속되면 각각 이해 확인·자세 안내 프롬프트를 띄운다. 연속 횟수와 카운터를 되돌리는 규칙은 [`attention-coaching-context.md`](./attention-coaching-context.md) §4.1 을 따른다.
- 모델이나 MediaPipe 를 불러오지 못하면 **판정을 비활성**하고 수업은 그대로 진행한다. 룰 폴백은 두지 않는다.

### 11.5 검출기 출력과 학생 상태

층위가 둘이다.

**검출기 출력** — 브라우저가 만드는 관측값. 카메라·MediaPipe·모델을 묶은 검출기가 10초마다 내놓고, 프롬프트 발동 판단에 쓰이며 그대로 서버로 전송된다(§11.8). 4단계와 `UNMEASURABLE`·`CAMERA_OFF`·`DETECTOR_UNAVAILABLE` 을 합쳐 7종이며, 어느 값을 낼지 정하는 순서가 있다.

**참여 상태** — 집계에 쓰는 값. `GOOD` · `CONFUSED` · `MISSED` · `NON_RESPONSE` · `UNMEASURABLE` · `CAMERA_OFF` 여섯 가지다. 표기는 언더스코어로 통일한다. 서버로 직접 보내는 값이 아니라, 서버가 받은 두 스트림(10초 검출기 출력, 프롬프트 응답)에서 도출한다.

두 층위를 같은 이름으로 부르지 않는다. `UNMEASURABLE` 은 양쪽에 있지만 검출기 쪽은 10초 판정 한 건, 참여 상태 쪽은 3연속으로 확정된 값이다.

검출기 출력 7종과 판정 순서, 각 참여 상태의 확정 조건, 어떤 프롬프트를 띄우는지, 집단 트리거의 분자·분모에 들어가는지는 [`attention-coaching-context.md`](./attention-coaching-context.md) §1·§2 의 표를 따른다.

검출기가 못 도는 학생은 관측이 불가능하므로 분모에서 빠져야 한다. 그래서 `DETECTOR_UNAVAILABLE` 도 다른 상태와 똑같이 서버로 보낸다. 머지된 백엔드(티켓 78)는 참여 상태 6종만 받으므로 이 문서 기준으로 계약을 넓혀야 한다.

### 11.6 세 종류의 UNMEASURABLE

같은 이름이 세 층위에서 다른 뜻으로 쓰인다. **연결 불가**(LiveKit 재연결·재입장)는 분석 자체가 불가능해 판정을 만들지 않는다. **검출기 출력**(10초 창의 얼굴 검출 부족)은 판정 한 건이며 프롬프트로 이어지지 않는다. **참여 상태**(검출기 출력 3연속)만 자세 안내 프롬프트와 집단 트리거 분자로 이어진다.

구현에서 세 층위를 서로 다른 이름으로 부른다. 세 종류의 대비와 섞였을 때 생기는 오작동은 [`attention-coaching-context.md`](./attention-coaching-context.md) §11 을 본다.

### 11.7 학생에게 보이는 실시간 상태

실시간 강의실에서는 학생에게 단계·점수·세부 수치를 표시하지 않는다. 표시하는 것은 `분석 중`, `카메라 OFF`, `측정 불가`, `분석 비활성` 네 가지뿐이다. `분석 비활성`은 모델이나 MediaPipe 를 불러오지 못한 상태를 뜻한다. 수업 후 학생 리포트에서만 본인의 `집중 흐름(참고용)`을 제공한다. 리포트의 집중 흐름은 구간별 단계 평균이므로 단계 값을 담는다. 위 제한은 실시간 화면에만 적용된다.

### 11.8 판정 엔진 계약

- 판정 시작·종료 시각(10초 구간)
- 검출기 출력 7종 중 하나
- 신호 품질(유효 프레임 비율)
- `featureSchemaVersion`
- `engineVersion`

폴백을 두지 않으므로 `engineType` 구분은 없다. 모델을 못 불러오면 판정을 만들지 않고 `분석 비활성`로 표시한다.

4단계를 접지 않고 그대로 보내는 이유는 프롬프트 응답과 짝지어 모델을 개선하기 위해서다. 응답이 사실상 정답 레이블인데 그 시점 모델 출력이 없으면 쌍이 만들어지지 않는다. 단, 4단계 값은 집단 집계에 쓰지 않는다.

**네 단계 확률은 보내지 않는다.** §22.2 가 개인 모델 확률을 저장 금지 대상으로 규정한다. 확률은 브라우저 안에서 저참여 판정에만 쓰고, 서버로는 단계 라벨만 간다.

ZANI 특징 집계값을 모델 재학습에 사용하려면 일반 운영 저장과 분리된 연구 참여 동의를 받아야 한다.

## 12. 학생 확인 프롬프트

### 12.1 프롬프트 3종

프롬프트는 **이해 확인**, **자세 안내**, **카메라 안내** 세 가지다. 발동 조건·선택지·노출 시간·쿨타임과 표시 문구는 [`attention-coaching-context.md`](./attention-coaching-context.md) §5 를 따른다.

### 12.2 동작 규칙

- 프롬프트는 강의 내용을 가리는 전체 화면 모달이 아닌 하단 패널로 표시한다.
- 노출 시간이 지나면 자동으로 닫는다. **이해 확인**만 무응답이 상태로 남는다(`NON_RESPONSE`).
- 같은 학생에게 프롬프트를 다시 띄우려면 쿨타임이 지나야 한다. 쿨타임은 **프롬프트 종류별로 따로 잰다.**
- 프롬프트가 떠 있는 동안에는 연속 카운터를 멈추고, 닫힐 때 0으로 되돌린다. 학생이 하단 패널을 읽는 동안의 관측은 믿을 수 없기 때문이다.
- 카메라 안내의 응답은 집계를 바꾸지 않는다. 분모 제외는 `CAMERA_OFF`가 1분 이상 이어졌는지로 자동 판정하며, 카메라를 다시 켜면 즉시 분모에 복귀한다.
- "이해했어요"는 해당 구간의 개인 추천 우선순위를 낮추는 근거다.
- "헷갈려요"·"놓쳤어요"는 집단 팁과 개인 추천의 강한 근거다.
- `NON_RESPONSE`는 단독으로 이해도 라벨로 사용하지 않는다.

| ID | 요구사항 |
| --- | --- |
| PROMPT-001 | 저참여 판정이 정해진 횟수만큼 연속되면 이해 확인 프롬프트를 표시해야 한다(연속 횟수는 기준 문서 §4.1, 저참여 기준은 §3.3). |
| PROMPT-002 | 프롬프트는 노출 시간이 지나면 자동 종료되고 이해 확인은 `NON_RESPONSE`를 저장해야 한다(값은 기준 문서 §5). |
| PROMPT-003 | 이해 확인 프롬프트에 쿨타임을 적용해야 한다(값은 기준 문서 §5.3). |
| PROMPT-004 | 자세 안내 프롬프트에도 쿨타임을 적용해야 한다(값은 기준 문서 §5.1). |
| PROMPT-005 | 카메라 안내는 응답으로 집계를 바꾸지 않아야 한다. 분모 제외는 `CAMERA_OFF` 지속 시간으로 자동 판정한다(값은 기준 문서 §7.1). |
| PROMPT-006 | 응답과 발생 근거를 세션 상대 시각과 함께 저장해야 한다. |
| PROMPT-007 | 프롬프트가 떠 있는 동안 연속 카운터를 멈추고 닫힐 때 0으로 되돌려야 한다(기준 문서 §5). |
| PROMPT-008 | 쿨타임은 프롬프트 종류별로 따로 관리해야 한다(기준 문서 §5). |

## 13. 강사 집단 팁

### 13.1 개인정보 원칙

- 강사는 학생별 자동 분석 상태와 학생별 응답을 볼 수 없다.
- 강사는 최근 구간의 전체 비율, 응답 분포, 팁 유형만 본다.
- 학생별 데이터는 해당 학생의 개인 복습 추천에만 사용한다.

### 13.2 분모·분자와 발동

집단 팁은 **접속 1분을 넘긴 학생** 중 **최근 관찰 창 안에서 확인이 필요했던 고유 학생**의 비율이 임계값을 넘으면 발송하고, 이후 일정 시간 동안은 팁 유형과 무관하게 다시 보내지 않는다. 측정 가능 학생 비율에 대한 전제 조건은 두지 않는다.

분모에서 제외되는 학생, 분자에 들어가는 상태, 관찰 창 길이·임계값·쿨타임의 실제 값은 [`attention-coaching-context.md`](./attention-coaching-context.md) §7 을 따른다.

### 13.3 팁 유형 선택과 문구

팁은 5종이며, 어떤 유형을 고를지의 규칙은 [`attention-coaching-context.md`](./attention-coaching-context.md) §7.6, 표시 문구 전문은 §8 을 따른다. `{핵심 개념}`·`{핵심 내용}` 자리표시자는 온디맨드 전사 결과로 채운다(§14).

### 13.4 표현과 동작

강사는 팁을 `확인`하거나 `닫기`만 할 수 있다. 유용성 평가 버튼은 제공하지 않는다. 팁은 한 번에 하나만 표시한다.

| ID | 요구사항 |
| --- | --- |
| ALERT-001 | 집단 비율은 1분 유예를 통과한 현재 접속 학생을 분모로 계산해야 한다. |
| ALERT-002 | 관찰 창 안의 유의 학생 비율이 임계값 이상이면 집단 팁을 생성해야 한다(값은 기준 문서 §7). |

| ALERT-005 | `CAMERA_OFF`나 `DETECTOR_UNAVAILABLE`이 1분 이상 이어진 학생을 분모에서 제외하고, 그 상태에서 벗어나면 즉시 복귀시켜야 한다(기준 문서 §7.1). |

## 14. 실시간 온디맨드 전사

### 14.1 오디오 버퍼

강사 브라우저는 자신의 마이크 트랙을 복제해 최근 구간을 링버퍼로 유지하고, 트리거가 발생하면 버퍼 전체를 업로드한다. 강사 마이크가 꺼져 있으면 업로드하지 않는다. 버퍼 길이는 [`attention-coaching-context.md`](./attention-coaching-context.md) §9 을 따른다.

### 14.2 전사와 팁 생성

- 업로드된 오디오가 최소 길이에 미치지 못하면 **전사하지 않고 팁도 보내지 않는다.** 이 경우 쿨타임도 시작하지 않는다(최소 길이는 [`attention-coaching-context.md`](./attention-coaching-context.md) §9).
- 전사는 SSAFY GMS `whisper-1`을 사용하고 timeout 10초, 재시도 없음으로 호출한다.
- 전사 결과를 LLM에 넘겨 `{핵심 개념}`·`{핵심 내용}`을 채운 팁 JSON을 만든다. 허용된 액션 스키마를 벗어난 응답은 폐기한다.
- 오디오 원본은 전사 직후 폐기한다.

## 15. 녹화

### 15.1 녹화 범위

- 강사 카메라 영상
- 현재 활성화된 공유 화면(공유자의 역할과 무관)
- 강사와 학생의 전체 발화 음성
- 학생 발화자를 식별할 수 있는 오디오 트랙 메타데이터

학생 카메라 영상은 녹화에서 제외한다. 공유 화면이 없으면 강사 카메라를 주 화면으로, 공유 화면이 있으면 공유 화면을 주 화면으로 하고 강사 카메라를 보조 화면으로 합성한다.

### 15.2 저장과 처리

- 녹화는 LiveKit Track Egress로 참가자·트랙별 원본을 만들고, 수업 종료 후 시간축을 정렬해 최종 MP4로 병합한다.
- 저장소는 **EC2 로컬 디스크**다. S3는 사용하지 않는다.
- 녹화 산출물의 참가자 식별자는 익명 별칭(`instructor`, `student-001`)만 사용한다. 실명·이메일·내부 ID를 경로나 manifest에 넣지 않는다.
- 학생 카메라는 Egress 요청 자체를 생성하지 않는다.
- Egress 시작은 outbox로 기록한 뒤 릴레이가 수행하며, 중복 시작을 세 겹으로 막는다(dedup key, claim, 기존 Egress 채택).

### 15.3 녹화 상태

- 녹화 중임을 모든 참여자에게 항상 표시한다.
- Egress가 실패하면 강사에게 표시하고 지수 백오프로 재시도한다. 상한을 넘기면 실패로 남긴다.
- 녹화가 완전하지 않으면 처리 상태와 운영 로그에 누락 구간과 사유를 기록하고 가능한 데이터만 분석한다.

| ID | 요구사항 |
| --- | --- |
| RECORD-001 | 방 생성 성공과 함께 녹화를 시작해야 한다. |
| RECORD-002 | 강사 카메라·현재 공유 화면·전체 음성을 합성 녹화해야 한다. |
| RECORD-003 | 학생 카메라 영상은 녹화물에 포함하지 않아야 한다. |
| RECORD-004 | 전사 화자 매핑을 위해 사용자별 오디오 트랙 식별 정보를 보존해야 한다. |
| RECORD-005 | 녹화 실패·누락 구간을 처리 상태와 운영 로그에 기록해야 한다. |

## 16. 수업 종료 후 강사 메모

- 수업 중 중요 구간 표시 버튼은 제공하지 않는다.
- 종료 후 강사는 녹화를 탐색하고 하나 이상의 구간에 메모를 남길 수 있다.
- 메모는 개념명, 강조 이유, 학생이 다시 볼 포인트를 자유 형식으로 작성한다.
- 수업 종료 시 30분 비활성 타이머를 시작하고, 입력을 감지할 때마다 초기화한다.
- `작성 완료`를 누르면 즉시 확정하고, 30분간 입력이 없으면 자동 확정한다.
- 확정 후에는 수정·재생성할 수 없다.

| ID | 요구사항 |
| --- | --- |
| NOTE-001 | 강사는 종료 후 녹화 구간과 메모를 연결할 수 있어야 한다. |
| NOTE-002 | 입력 감지 시 30분 비활성 타이머를 초기화해야 한다. |
| NOTE-003 | 수동 완료 또는 30분 비활성 시 메모를 한 번만 확정해야 한다. |
| NOTE-004 | 메모 확정 후 전사·AI 분석 작업을 시작해야 한다. |

## 17. 사후 전사·멀티모달 AI 분석

### 17.1 처리 순서

```
강사 메모 확정
→ 녹화 파일 무결성 확인
→ 오디오 추출과 전사
→ 전사 화자·타임스탬프 정렬
→ 자막 기반 개념 구간 분할과 질문 연결
→ 10~15분 영상 청크 생성
→ 사용자 메타데이터 가명화
→ SSAFY GMS 멀티모달 분석
→ 구조화 결과 자동 근거 검증
→ 개인·집단 타임라인과 수업 품질 피드백 생성
→ 공통·강사·학생 결과 조립
→ 권한별 공개
→ 완료 이메일 발송
```

### 17.2 전사

- 전사는 시작·종료 시각, 발화 텍스트, 화자 식별자, 신뢰도를 가져야 한다.
- 공통 전사 UI에는 참여자의 실제 표시 이름을 보여준다.
- 지원 언어의 우선순위는 한국어다.
- 어디서 전사를 실행하는지는 이 문서가 정하지 않는다. 요구는 위 네 항목과 8시간 SLA(`AI-006`)뿐이다.

### 17.3 GMS 입력과 가명화

10~15분 단위 녹화 청크, 가명화된 화자 식별자가 포함된 전사, 학생별 가명화 이벤트와 응답, 집단 반응 이벤트, 공개 채팅, 허용된 1:1 채팅, 확정된 강사 메모를 보낸다. 이름·이메일·Google 식별자·내부 사용자 ID는 보내지 않는다. 영상 속 얼굴·음성처럼 미디어 자체에 포함된 정보는 완전 익명화가 불가능하므로 이 처리를 `메타데이터 가명화`로 정의한다.

### 17.4 비언어 정보 활용

강사의 손짓·가리키기·큰 동작을 강조 구간의 보조 신호로만 사용한다. 강사의 감정·성격·역량을 평가하지 않는다. 학생 카메라 영상은 사후 분석 입력에 포함하지 않는다.

### 17.5 구조화 출력과 자동 검증

각 결과 항목은 녹화 시각, 전사 청크 ID, 이벤트 ID, 메모 ID, 개념 구간 ID, 추천 개념명·요약·이유, 피드백 유형·신뢰도·근거·제안을 구조화해 반환한다. 시스템은 시각이 실제 녹화 범위 안인지, ID가 같은 수업의 것인지 검사하고 실패한 항목만 제거한다.

### 17.6 개념 구간과 질문 연결

- 전사와 화면 내용으로 개념별 대표 설명 구간의 시작·종료 시각을 만든다.
- 질문 작성 시각과 질문이 대상으로 하는 개념 설명 구간을 서로 다른 값으로 저장한다.
- 신뢰도가 낮으면 질문 시점 전후 60초를 임시 구간으로 사용하고 자동 연결임을 표시한다.
- 복습 링크는 질문 시각이 아니라 개념 설명 구간의 시작 시각으로 이동한다.

### 17.7 수업 품질 피드백 원칙

- 학생 카메라 신호 하나로 생성하지 않고 익명 집단 흐름, 자기보고, 질문, 전사, 개념 경계, 발화 속도, 공개 상호작용과 강사 메모를 결합한다.
- 개념 명확성, 수업 속도·정보량, 상호작용 효과, 개념 전환, 흐름 회복, 잘된 설명 방식으로 구분한다.
- 각 피드백은 구간, 근거, `높음·중간·낮음` 신뢰도, 제안, 녹화 링크를 가진다.
- 낮은 신뢰도는 평가가 아닌 `검토 후보`로 표현하고, 수업 전체를 단일 점수로 축약하지 않는다.

## 18. 강사 리포트

### 18.1 공통 수업 자료

수업 기본 정보와 실제 시간, 참여자 수, 전체 녹화와 실명 화자 전사, 시간대별 요약·챕터·핵심 개념, 공개 질문·채팅 요약, 강사에게 온 1:1 질문과 연결된 개념 구간, 강사 메모와 AI가 연결한 강조 구간을 제공한다.

### 18.2 익명 집단 집중 흐름 타임라인

강사에게 보이는 주 계열은 집단 집중 흐름이다. 겹치지 않는 30초 구간마다 값을 하나 제공한다.

```
집단 집중 흐름(구간)
= 그 구간에 값이 있는 집계 대상 학생들의 개인 집중 흐름 값 평균
```

- 값은 1~4 범위이며 개인 집중 흐름(§19.2)과 같은 척도다.
- 값이 없는 학생은 평균에서 빠진다. 빠진 학생을 1단계로 채우지 않는다.
- 학생별 값은 응답에 담지 않는다. 강사는 평균만 본다.
- 수업 내용이 바뀌는 지점으로 나눈 구간마다 그 구간의 집중 흐름 평균을 함께 제공한다. 고정 길이로 끊지 않는다.

흐트러짐 구간 판정(§18.3)과 실시간 코칭에 쓰는 확인 필요 학생 비율은 별도 계열로 계속 제공한다. 이 값은 수업 시간축에 맞춰 5초마다 계산한다.

```
확인 필요 학생 비율(t)
= 최근 5분에 CONFUSED·MISSED·NON_RESPONSE·UNMEASURABLE 이 발생한 집계 대상 고유 학생 수
  ÷ 해당 시점의 집계 대상 학생 수
```

- 집계 대상은 해당 시점에 연결되어 있고 연속 접속 1분이 지난 학생이다. 두 계열 모두 같은 집계 대상을 쓴다.
- `CAMERA_OFF`가 연속 1분 이상 이어진 학생은 분모에서 제외하고, 카메라 OFF 학생 비율을 별도 계열로 제공한다. 카메라를 다시 켜면 즉시 분모로 돌아온다.
- 분자에 들어가는 창(5분)과 남는 기간, `UNMEASURABLE`의 확정 조건은 [`attention-coaching-context.md`](./attention-coaching-context.md) §7.3 을 따른다.
- 집계 대상이 5명 미만이면 비율을 숨기고 `집계 인원이 부족합니다`로 표시한다.
- 같은 시간축에 측정 가능 비율, 응답 분포, 질문 밀도, 개념·챕터 구간, 흐트러짐 구간, 상호작용 시점, 집단 팁과 메모 시점을 정렬한다.
- 그래프·구간을 클릭하면 관련 녹화 시각으로 이동한다.

### 18.3 집중 흐트러짐 동적 구간

- 확인 필요 비율이 30% 이상으로 20초 지속되면 시작한다.
- 20% 미만으로 30초 유지되면 종료한다.
- 두 구간 간격이 15초 미만이면 병합한다.
- 경계 15초 이내에 개념·챕터·문장 경계가 있으면 그 경계로 보정한다.
- 임계값은 원격 설정으로 조정할 수 있어야 한다.

### 18.4 수업 품질 피드백

개념 명확성, 수업 속도·정보량, 상호작용 효과, 개념 전환, 흐름 회복, 잘된 설명 방식 차원으로 제공하며, 각 카드는 관련 개념과 시각, 녹화 링크, 익명 집계 근거, 신뢰도, 구체적 제안을 포함한다. 전체 수업에 단일 품질 점수나 등급을 부여하지 않는다.

### 18.5 개인정보 원칙

강사는 학생별 자동 분석 상태·응답·집중 흐름·복습 추천을 볼 수 없고, 익명 그래프에서 개인 목록으로 가는 드릴다운도 제공하지 않는다.

## 19. 학생 리포트와 복습 추천

### 19.1 공통 자료

실제 입장 기록이 있는 학생은 녹화, 실명 화자 전사, 시간대별 요약, 공통 핵심 개념, 공개 질문·채팅 요약을 볼 수 있다. 다른 학생의 1:1 메시지는 볼 수 없다.

### 19.2 개인 집중 흐름 타임라인

```
집중 흐름(구간)
= 그 구간에서 나온 4단계 판정의 단계 평균
```

- 겹치지 않는 30초 구간마다 값을 하나 제공한다. 이동창으로 계산하지 않는다.
- 값은 1~4 범위이며 다른 척도로 환산하지 않는다.
- 4단계 판정만 평균에 들어간다. `UNMEASURABLE`·`CAMERA_OFF`·`DETECTOR_UNAVAILABLE`은 단계가 없어 평균 대상이 아니다.
- 구간의 측정 가능 시간이 70% 미만이면 값을 계산하지 않고 회색 공백으로 표시한다. 여기서 "측정 가능"은 참여 상태가 `UNMEASURABLE`·`CAMERA_OFF`가 아닌 시간을 뜻하며, 판정 한 건의 유효 프레임 비율(기준 문서 §3.2)과는 다른 값이다.
- `CAMERA_OFF`와 `UNMEASURABLE`은 1단계로 표시하지 않는다. 낮은 참여도와 측정 실패는 다른 사건이다.
- 수업 내용이 바뀌는 지점으로 나눈 구간마다 그 구간의 집중 흐름 평균을 함께 제공한다. 고정 길이로 끊지 않는다.
- 하단 상태 막대로 확인 필요 구간, 카메라 OFF, 측정 불가를 구분한다.
- 확인 프롬프트, 질문, 중요 개념, 복습 구간을 같은 시간축에 표시하고 클릭 시 녹화로 이동한다.
- 색상만으로 구분하지 않고 텍스트·아이콘·패턴을 함께 사용한다.
- 수업 전체를 하나의 점수로 축약하거나 다른 학생과 비교하지 않는다.

### 19.3 개인 복습 추천

근거가 있는 경우에만 0~5개 제공하며, 각 추천은 개념명, 구간 시각, 이유, 복습 포인트, 다시 보기 링크, 관련 질문, 사용 근거 유형을 가진다.

우선순위는 ① "헷갈려요"·"놓쳤어요"로 응답한 개념 구간 ② 질문한 개념 구간 ③ `NON_RESPONSE`와 반복된 확인 필요 상태가 함께 있는 구간 ④ 중요 개념에서 확인 필요 상태가 반복된 구간이다. 단일 이벤트만으로는 추천을 만들지 않는다. "이해했어요"는 우선순위를 낮춘다.

### 19.4 개념 확인 복습 퀴즈

학생 리포트에서 그 수업의 핵심 개념을 스스로 확인하는 용도로만 제공한다. 문항은 수업 내용에서 만들고, 학생은 풀이 직후 정답과 해당 개념의 녹화 구간을 확인할 수 있다.

점수를 누적하거나 회차 간 이력을 쌓지 않는다. 결과를 강사에게 보여주지 않고, 성적·평가·복습 추천 우선순위에 반영하지 않는다.

| ID | 요구사항 |
| --- | --- |
| REPORT-S-001 | 실제 입장 기록이 있는 학생에게 공통 녹화·전사를 제공해야 한다. |
| REPORT-S-002 | 학생에게 본인 데이터로 생성된 추천만 0~5개 제공해야 한다. |
| REPORT-S-003 | 추천은 검증된 구간과 이유를 함께 표시해야 한다. |

## 20. 결과 알림과 처리 상태

- 수업 목록에는 `LIVE`, `강사 메모 대기`, `분석 중`, `완료`, `분석 실패`, `삭제됨` 상태를 표시한다.
- 별도 서비스 내 알림 배지는 제공하지 않는다.
- 전체 결과가 완료되면 Google 계정 이메일로 한 번 알린다.
- 완료 알림은 계정 설정에서 끌 수 있고 기본값은 켜짐이다. 끈 사용자에게 보내지 않은 것은 발송 실패가 아니므로 장애로 기록하지 않는다. 이 설정은 완료 알림에만 적용되고 분석 실패 통보에는 적용되지 않는다.
- 이메일 링크는 로그인 후 권한을 다시 확인한다.
- 이메일 발송 실패해도 결과는 유지하고 운영 로그에 남긴다.
- 분석이 최종 실패하면 강사에게 실패 이메일을 보내고 학생에게는 공개하지 않는다.

| ID | 요구사항 |
| --- | --- |
| NOTIFY-001 | 전체 결과 완료 후 권한 보유자에게 이메일을 발송해야 한다. 완료 알림 수신을 끈 사용자에게는 발송하지 않아야 한다. |
| NOTIFY-002 | 이메일 링크 접근 시 인증과 세션 참여 권한을 다시 확인해야 한다. |
| NOTIFY-003 | 이메일 실패와 분석 실패를 구분해 기록해야 한다. |
| NOTIFY-004 | 완료 알림 수신 여부를 계정 설정에서 바꿀 수 있어야 하고 기본값은 켜짐이어야 한다. |

## 22. 데이터 보관·삭제·감사

### 22.1 저장하는 데이터

계정과 약관 동의, 수업방·참여 관계·입출입 시각, 10초 판정 구간(검출기 출력)과 신호 품질, 스키마·엔진 버전, 확인 프롬프트와 응답, 채팅·손들기·반응 이벤트, 녹화, 전사·개념 구간·강사 메모·AI 결과·근거 연결, 개인·집단 타임라인 결과, 수업 품질 피드백, 실시간 팁 이력, 이메일·접근 감사 로그.

### 22.2 저장하지 않는 데이터

학생 원본 카메라 녹화·프레임, 랜드마크 원본, 프레임별 특징값, 일반 사용자의 10초 입력 텐서(`20 × 98`), 개인 모델 확률·이해도 확정값·순위. 실시간 전사에 쓰인 강사 오디오는 전사 직후 폐기한다.

### 22.3 보관과 삭제

- 수업 데이터는 종료 90일 후 자동 삭제한다.
- 강사는 90일 전에 수업 단위로 수동 삭제할 수 있고 복구는 제공하지 않는다.
- 삭제 실패는 재시도 큐에 넣고 운영 경고를 발생시킨다.

- 저장소: **EC2 로컬 디스크** (S3 미사용)
- 컴퓨트: AWS EC2 기반 컨테이너 배포
- 브라우저 분석: MediaPipe 특징 추출 + 온디바이스 참여도 모델(ONNX). 폴백 없음
- 실시간 전사·팁: SSAFY GMS whisper-1 + LLM
- 사후 멀티모달 분석: SSAFY GMS
- 인증: Google OAuth + JWT(Access 헤더 / Refresh 쿠키)
- 완료 알림: 이메일

서비스 경계는 인증·수업 API, 실시간 미디어, 브라우저 특징 추출·판정, 이벤트 집계·트리거, 실시간 전사·팁, 녹화·병합, 사후 전사·GMS 분석, 타임라인·리포트, 권한·삭제·감사로 나눈다.
