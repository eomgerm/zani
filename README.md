# ZANI

> **비대면 강의에서 학생의 학습 반응을 읽어, 강사에게는 지금 필요한 조언을, 학생에게는 자기 수업의 기록을 남깁니다.**

<br>

## 이 프로젝트가 푸는 문제

대면 강의에서 강사는 학생들의 표정만 보고도 "지금 안 통했다"를 압니다. 비대면에서는 그 신호가 사라집니다.

카메라를 켜 두어도 30명의 얼굴을 동시에 읽을 수는 없습니다. 학생도 마찬가지입니다. 이해하지 못했다는 걸 실시간으로 말하기 어렵고, 수업이 끝나면 **어디를 다시 봐야 하는지조차** 기억나지 않습니다.

ZANI는 그 사라진 신호를 되살립니다.

- 학생 브라우저가 카메라 영상을 **직접 분석**해 참여 상태를 판정합니다. 영상은 서버로 보내지 않습니다.
- 흐트러진 학생에게는 조용히 확인 질문을 띄우고, 그 응답을 익명으로 모아 **강사에게 "지금 30%가 헷갈려 합니다"**를 알립니다.
- 수업이 끝나면 녹화·전사·참여도를 하나의 시간축에 겹쳐, 강사에게는 개선 피드백을, 학생에게는 자기가 놓친 구간의 복습 클립을 만들어 줍니다.

<br>

## 핵심 기능

### 1. 브라우저에서 끝나는 참여도 판정

학생 카메라 영상은 **서버로 전송되지 않습니다.** 브라우저가 MediaPipe로 얼굴 특징을 뽑고, 온디바이스 ONNX 모델이 10초 단위로 참여 단계를 판정합니다. 서버로 가는 것은 판정 결과뿐입니다.

```
카메라 → MediaPipe 얼굴 특징 → 10초 창 → ONNX 4단계 판정 → 결과만 서버로
                                                    ↑
                                    원본 영상·랜드마크는 브라우저를 떠나지 않음
```

오탐을 줄이려고 **한 번의 판정으로 개입하지 않습니다.** 저참여가 3연속(30초) 이어질 때만 학생에게 확인 질문을 띄웁니다. 실측으로 90분 수업당 잘못 뜨는 횟수를 0.5회 수준까지 낮췄습니다.

### 2. 익명 집단 신호와 실시간 강사 팁

개별 학생의 상태는 강사에게 보이지 않습니다. **익명으로 집계된 비율만** 전달됩니다.

최근 5분 안에 확인이 필요했던 학생이 30%를 넘으면, 그 시점 강사 발화를 전사해 **"어떤 개념을 다시 설명해야 하는지"**까지 담은 팁을 띄웁니다.

> **추가 설명이 필요해요**
> 전체 학생의 **30%가 현재 내용을 헷갈려 하고 있어요.**
> {핵심 개념}을 다른 예시로 다시 설명해 주세요.

### 3. 트랙별 녹화와 화자 분리

강사 카메라·마이크·화면공유, 학생별 마이크를 **각각 따로** 녹화합니다. 학생 카메라는 저장하지 않습니다.

따로 저장하기 때문에 학생별 전사와 화자 구분이 가능하고, 최종 영상을 만들 때만 시간축을 맞춰 하나로 합칩니다. 파일명과 메타데이터에는 실제 이름 대신 익명 별칭(`student-001`)만 씁니다.

### 4. 수업 종료 후 리포트

**강사** — 수업 구간별 평균 참여도를 색으로 보여주고, 분야별 평가와 개선 팁을 함께 제공합니다. 개별 학생의 데이터는 볼 수 없습니다.

**학생** — 자기 참여도 흐름, 놓친 구간의 복습 클립, 수업 내용 기반 퀴즈를 받습니다. 다른 학생과 비교하지 않고 평균 점수로 축약하지도 않습니다.

## 설계에서 신경 쓴 것

포트폴리오로 봐 주실 분들께 이 프로젝트의 판단들을 남깁니다.

**학생 영상을 서버로 보내지 않는다.** 판정을 브라우저에서 끝내는 구조는 서버 추론보다 어렵습니다. 모델을 ONNX로 변환해 브라우저에서 돌려야 하고, 기기 성능 차이를 흡수해야 합니다. 그래도 이 방향을 택한 이유는, 강의실 30명의 얼굴을 서버에 올리는 설계를 만들고 싶지 않았기 때문입니다.

**측정을 회피하는 것이 이득이 되지 않게 만든다.** 초기 설계에서는 "카메라를 못 켜요"에 응답하면 집계에서 빠졌습니다. 그러면 모두가 그 버튼을 누르는 게 유리해집니다. 카메라가 실제로 꺼져 있는 시간으로 자동 판정하도록 바꿨습니다. 같은 이유로, 화면을 벗어난 학생을 집계에서 빼지 않습니다 — 그러면 듣기 싫을 때 나가버리는 게 유리해집니다.

**임계값에 근거를 남긴다.** "저참여로 볼 확률 0.35", "3연속 요구" 같은 값은 감으로 정하지 않았습니다. EngageNet 테스트셋 2,014건으로 기준값별 검출률과 오탐률을 재고, 90분 수업당 잘못 뜨는 횟수까지 계산해 골랐습니다. 근거가 없는 값(예: 유효 프레임 70%)은 **근거가 없다고 문서에 적어 뒀습니다.**

**문서에 구현 상태를 적지 않는다.** 진행 상황을 문서에 옮겨 적으면 반드시 낡습니다. 실제로 3일 만에 여러 항목이 뒤집힌 것을 확인하고, 문서는 기준만 담고 진행 상황은 Jira, 코드 사실은 코드가 정본이 되도록 정리했습니다.

## 기술 스택

### Frontend

`Next.js` · `TypeScript` · `React` · `Zustand` · `TanStack Query` · `Vitest`

실시간 미디어는 `LiveKit SDK`, 참여도 판정은 `MediaPipe Face Landmarker` + `ONNX Runtime Web`

### Backend

`Java 21` · `Spring Boot` · `Spring Security` · `MySQL` · `Redis` · `Flyway`

실시간 업무 이벤트는 `STOMP over WebSocket`, 미디어 제어는 `LiveKit Server SDK`

### AI

`Python` · `PyTorch` · `MediaPipe` · `ONNX`

참여도 4단계 분류 모델을 EngageNet으로 학습해 브라우저 추론용 ONNX로 배포합니다.
전사와 생성형 분석은 `SSAFY GMS`(whisper-1 · LLM)를 사용합니다.

### Infrastructure

`LiveKit SFU` · `LiveKit Track Egress` · `FFmpeg` · `Docker Compose` · `Nginx` · `Jenkins`

프론트엔드는 Vercel, 나머지는 SSAFY EC2 한 대에 컨테이너로 올립니다. 녹화 파일은 오브젝트 스토리지를 쓰지 않고 EC2 로컬에 두고, 권한 검사를 거쳐 Nginx 내부 전달로 제공합니다.

### 협업

`GitLab` · `Jira` · `Notion` · `Figma`

Merge Request마다 Jenkins가 Git 컨벤션·DDD 경계 위반을 기계 검사하고, Claude Code가 재사용 가능한 컴포넌트와 중복 구현을 검토해 댓글로 남깁니다.

## 실행 방법

### 사전 준비

- Java 21, Node.js 20+, Python 3.12+, Docker
- LiveKit 서버 (로컬은 `infrastructure/local` 참고)

### Frontend

```bash
cd fe
npm install
npm run dev
```

### Backend

```bash
cd backend
./gradlew bootRun          # macOS · Linux
gradlew.bat bootRun        # Windows
```

### AI

```bash
cd ai
uv sync --all-extras
uv run zani-ai --help
```
